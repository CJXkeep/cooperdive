### 1.2 三个必须记住的坑

1. **`ak.macro_china_bsi_index()` 不是 BSPI**——它是「超灵便型船运价指数」（东财 EMI00107667）。按函数名猜接口必踩坑。
2. **两个公告接口只返回「标题 + 链接」，不含正文数值**。运量数字必须再走 PDF 解析，这是本项目**真正的工程量所在**，不是调一个函数就完事。
3. **`ak.futures_zh_daily_sina` 源码自带「容易封禁 IP」警告**——无人值守场景必须改用 `ak.futures_hist_em`。

### 1.3 对事件样本的数据可用性矩阵（关键结论）

| 数据 | 2008 | 2015 | 2020 |
|---|---|---|---|
| 601006 / 沪深300 日线 | ✅ | ✅ | ✅ |
| 美债 10Y | ✅ | ✅ | ✅ |
| 大秦线运量同比 | ⚠️ 手工（年报回填约 12 条） | ⚠️ 公告 PDF（起始年份待验证） | ✅ |
| 沿海电厂可用天数（D5） | ❌（2016 才有） | ❌ | ❌（**M1 实测停更于 2019-06** → D-26） |
| 秦皇岛库存（D1/D2/D3） | ❌ | ❌ | ❌（仅手工） |

> **这条矩阵直接决定迭代顺序**：
> - **2008「核心样本」实际上只能验证 M+K 链路**，D 系列全降级；
> - **D 系列只有 2020 一个样本**，且仅靠自动可得的 D4（运量同比）+ D5（电厂可用天数）支撑；
> - 所以必须**先做 2020 闭环**，否则会把大量时间投进一个无法验证的分支。

## 2. 设计决议（ADR）

| 编号 | 决议 | 理由 / 影响 |
|---|---|---|
| **D-01** | FRED 改用免 key 的 `fredgraph.csv` 端点；`requirements.txt` **不加 fredapi** | 已实测无需 key、历史同样完整；少一个依赖、少一个必须配的环境变量。`daqin/collectors/fred.py` 用 `requests` + `pd.read_csv(StringIO(...))` |
| **D-02** | D1/D2/D3（秦皇岛库存）从核心规则降为**可选手工子集**，`demand.qhd_enabled` 控制，默认 `false` | 无免费自动源；手工周录约 5 分钟/周。默认关 = 开箱即用；有数据时打开即可增强 |
| **D-03** | `demand_bad` 重构为：**自动核** = D4 ∨ D5；**增强项** = D1 ∨ D2 ∨ D3（仅 `qhd_enabled` 时参与） | 原设计「D 系列是补跌预警核心」在数据不可得时不成立。运量同比 + 电厂可用天数两项均可自动获取，足以支撑需求恶化判定 |
| **D-04** | **旬度运量口径作废**。D4 只用月度；`dq_10d_volume_yoy` 从 metrics 与 DDL 中移除 | 免费源不存在。03 §7 提到的「旬度缓解月度滞后」失去依据，改为在报告中量化滞后 |
| **D-05** | 煤价用 **ZC 期货收盘价做粗代理**，配成交有效性过滤；D6 改为「ZC 收盘价低于 20 日均价 X%」而非「跌破长协基准价」 | BSPI 不可得；长协基准价本身需人工维护，砍掉。ZC 流动性差，须过滤无成交合约 |
| **D-06** | **坑口-港口价差、BSPI 指数本身 MVP 砍掉**，DDL 移除 `pit_port_spread`；保留扩展点 | 投入产出比最差的两项 |
| **D-07** | 电厂口径统一为「**沿海六大电**」，全文停止使用「沿海八省」，并注明样本差异 | 与唯一自动源对齐，避免文档写八省、代码取六电 |
| **D-08** | **S3 仓位统一为 20%（`s3_floor`）**，01 §4 表格「≤40% 下限再降」的表述作废 | 01 与 03 矛盾；以 thresholds.yaml 的 `s3_floor: 0.20` 为准 |
| **D-09** | `signal_log` 改为**每日一行快照**（`date` 主键），增加 `changed` 布尔与 `position_advice`，而非「仅状态变化写一行」 | DDL 的 `date PRIMARY KEY` 与 03 §4 文字矛盾；每日快照才能画状态色带，也让看板/回测共用同一张表 |
| **D-10** | **补齐状态机降级路径**：S4/S5 期间若 K2 或 K3 成立，立即回 S3 | 原转换矩阵只有 S4→S5、S5→S0，**没有从 S4/S5 回到高风险状态的路径**——2020 型「底部观察后再暴跌」会直接失效。这是本次评审发现的唯一逻辑漏洞 |
| **D-11** | 新增 `daqin/config.py` 与 `daqin/thresholds.py`（YAML 加载 + dataclass + 缺键报错），补进目录结构 | 02 §5 引用了 `daqin/config.py` 但 01 §2.3 目录结构漏列；「代码不得内嵌阈值」需要加载器与校验器才可执行 |
| **D-12** | `metrics_daily` **补齐信号层所需全部列**（见 §3），并增加数据截止标注列 | 原 02 §1.6 缺 7 个字段，其中 `rel_strength_20d_lag1`（K1「由正转负」）、`daily_return_pct`（K2）、`daqin_close`（K3）缺了信号层根本无法运行 |

| **D-14** | 看板：**单服务多页面**，`daqin/dashboard/app.py` 作为 copper 服务的附加页面（`st.navigation`）；不新增容器 | 已确认。零额外运维；streamlit>=1.59 已支持 `st.navigation` |

## 3. `metrics_daily` 修订版 DDL（修订 02 §1.6 / §4.1）

信号层是**只读 `metrics_daily` 单行的纯函数**，因此所有跨周期判定必须在指标层预计算为日频列。

```sql
CREATE TABLE IF NOT EXISTS macro_daily (          -- FRED 原始
  date TEXT PRIMARY KEY, us10y REAL, us10y_real REAL, us10y_ie REAL);

CREATE TABLE IF NOT EXISTS stock_daily (          -- 行情原始
  date TEXT PRIMARY KEY,
  daqin_close REAL, daqin_high REAL, daqin_low REAL,
  daqin_volume REAL, daqin_amount REAL,
  daqin_pb REAL, daqin_pe_ttm REAL,
  csi300_close REAL);

CREATE TABLE IF NOT EXISTS futures_daily (        -- ZC 动力煤主连（D-05 煤价代理）
  date TEXT PRIMARY KEY, zc_close REAL, zc_volume REAL, zc_amount REAL, zc_hold REAL);

CREATE TABLE IF NOT EXISTS energy_daily (         -- 沿海六大电（D-07），2016-01-01 起
  date TEXT PRIMARY KEY, pp_stock REAL, pp_daily_consume REAL, pp_available_days REAL);

CREATE TABLE IF NOT EXISTS industry_weekly (      -- 手工 CSV（D-02，可选）
  week_end TEXT PRIMARY KEY, qhd_inventory REAL, source TEXT DEFAULT 'manual');

CREATE TABLE IF NOT EXISTS company_monthly (      -- 公告 PDF 解析
  month TEXT PRIMARY KEY,
  dq_line_volume REAL, dq_line_volume_yoy REAL,
  source TEXT, art_code TEXT, fetched_at TEXT);

CREATE TABLE IF NOT EXISTS dividend_events (      -- 分红派息（股息率 TTM 用）
  ex_date TEXT PRIMARY KEY, dps REAL, source TEXT);

CREATE TABLE IF NOT EXISTS holder_quarterly (     -- 筹码（仅日报展示，不参与转换）
  quarter TEXT PRIMARY KEY, inst_holding_ratio REAL, holder_count INTEGER);

CREATE TABLE IF NOT EXISTS metrics_daily (        -- 指标层唯一输出、信号层唯一输入
  date TEXT PRIMARY KEY,
  -- 宏观（t-1 对齐）
  us10y REAL, us10y_20d_chg REAL,
  dividend_yield_ttm REAL, spread_daqin_us10y REAL,
  -- 行情
  daqin_close REAL, daqin_pb REAL, daily_return_pct REAL,
  ma20 REAL, ma60 REAL, ma120 REAL, volume_ratio_5d REAL,
  ma60_below_streak INTEGER,
  -- 相对强弱
  rel_strength_20d REAL, rel_strength_20d_lag1 REAL, rs_60d_peak REAL,
  csi300_drawdown_20d REAL,

## 4. 迭代计划

> 各里程碑的**展开设计与实现记录**见 [`iterations/`](iterations/README.md)（按迭代拆分，含 note 实现记录，M0 起）；

### 4.0 总体策略：可行走骨架优先

**核心思路**：先用最短路径打通「配置 → 入库 → 指标 → 信号 → CLI」全链路，让 `python -m daqin.cli signal` 能在 2020 年真实数据上输出完整 S0-S5 状态序列——**哪怕 D 系列部分为 False**。骨架阶段就能暴露指标对齐、纯函数、回测复用这三类最贵的架构错误；然后再逐层填实。

> 反面做法：按 M1 数据层完整 → M2 → M3 顺序推进，等能跑信号时已经是第 5 天，才发现 `metrics_daily` 缺列或对齐函数无法复用，返工代价最大。

### 4.1 Gate 0：可行走骨架（0.5-1 天）

| 任务 | 内容 | 出口条件 |
|---|---|---|
| M0-1 | `daqin/config.py` + `daqin/thresholds.py`（YAML→dataclass + 缺键报错） | 改一个阈值能立即在 `cli signal` 生效；缺键时启动即报错 |
| M0-2 | `daqin/storage/db.py`：§3 全量 DDL + upsert + 内存库单测 | `pytest tests/daqin/test_db.py` 通过；重复写入幂等 |
| M0-3 | `collectors/akshare_stock.py`：601006 + 沪深300 日线 | 2020 区间入库，日期连续 |
| M0-4 | `collectors/fred.py`：`fredgraph.csv` 免 key（D-01） | DGS10 从 2006 起入库 |
| M0-5 | `indicators/align.py`：t-1 可得性对齐 + ffill，**实盘与回测共用** | 单测覆盖：宏观晚于 A 股收盘 → 取 t-1 |
| M0-6 | `signals/rules.py` + `state_machine.py`：**全部规则一次写全**（含未校准阈值、含 D-10 降级路径） | 纯函数签名符合 03 §3.4 |
| M0-7 | `daqin/cli.py`：`collect` / `compute` / `signal` | 见下 |

```

> Gate 0 通过即可确认架构成立。**这一步失败就地改设计，不要带着骨架缺陷往下走。**

### 4.4 M2 指标层（1-2 天）

按 §3 DDL 全列实现，四个子模块（`macro` / `market` / `demand` / `coal`）。

### 4.5 M3 信号层（1.5-2 天）

- 规则全量（M/D/K 三组）+ 状态机 + `Debouncer` + D-10 降级路径 + 每日 `signal_log` 快照。
- **参数化单测必须覆盖**：转换矩阵全部单元格（含 S0/S1→S3 跳级）、S4/S5→S3 降级、滞回未达解除阈值不降级、防抖未确认不转换、同日多条件冲突取高风险、`qhd_enabled=false` 时 D1-D3 恒 False。
- **验收**：`pytest tests/daqin/test_signals.py -q` 全绿；`signal_log` 每日一行且 `changed` 正确。

### 4.6 M4 回测 2020 闭环（2-3 天）

- `backtest/events.py`：2020 窗口 2020-01-10 ~ 2020-12-31，warm-up ≥120 交易日。
- `backtest/engine.py`：T 日收盘出状态 → T+1 开盘执行；现金不计息（`cash_yield=0` 默认，另出 1.5% 敏感性）；含 0.1% 单边成本敏感性版本。
- **防未来函数断言**：回测任一时点只能使用 ≤ 该时点可得的数据，引擎内置检查（D-13）。
- 输出物：`2020_states.png` / `2020_nav.png` / `2020_report.md`。
- **M4 验收**：报告显示 S2/S3 出现在 2020-02~03 区间附近（不晚于锚点后 20 个交易日），且策略最大回撤显著小于买入持有。

### 4.7 M5 扩展回测与校准（3-5 天）

- 2015 事件（M+K 全链路，D4 可用、D5 不可用）；
- 2008 事件（M+K，D 全降级；运量需手工回填约 12 条）；
- 校准纪律沿用 04 §6：单参数敏感性优先，仅对 4 个核心阈值做 ≤5×5 网格，**邻域平稳才采纳，对单事件恰好最优的参数一律不取**；
- 校准结果写回 `daqin/thresholds.yaml` 并在 `change_log` 记录日期与依据。

### 4.8 M6 告警 + 看板 + 部署（2-3 天）

- `alerts/`：钉钉 Webhook + SMTP 邮件；**仅状态变化时推送**，另有可选每日日报开关；
- 看板：单服务多页面（D-14），复用现有 dashboard 容器与 Caddy 域名/登录，**不新增容器**；
- `scripts/scheduler.py`：21:30 轮次在 copper 采集后追加 `daqin collect → compute → signal`，沿用 copper 的单点失败隔离；
- **M6 验收**：构造一次 S2 触发可收到推送；`docker compose --profile prod up -d --build` 后 daqin 页面随 copper 一起服务。
