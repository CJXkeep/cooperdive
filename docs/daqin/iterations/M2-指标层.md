## 5. 实现记录

- **2026-09-22 结构拆分**：`daily.py` 从单文件（200+ 行）拆为四子模块 + 编排器。
  选择：`macro` / `market` / `demand` / `coal` 各暴露 `add_xxx(conn, m)`，自己读 raw 表、原地写列。
  Alternatives：① 保留单文件——列一多就难以定位，且单测只能整体断言，否决；② 各模块返回 DataFrame 再由编排器 merge——列名冲突与对齐责任会被抬高到编排器，反而更绕。
  代价：`uncovered_columns()` 需要维护 `ALL_METRIC_COLS` 清单，但换来**新增列漏接会立刻失败**（见下条）。
- **2026-09-22 自检机制立刻见效**：`uncovered_columns()` 首次运行即报 `{'asof_company'}`——该列在 `add_volume` 中写入但未登记，说明手工维护清单确实容易漏；已修正并加单测（`test_metric_columns_fully_covered`）。
  **这与 D-25/D-22 同类**：靠"记得写"不可靠，需要可执行的检查。
- **2026-09-22 qhd 增强列补齐**：D1/D2/D3 依赖的 5 列（`qhd_inv_level/wow/yoy/wow_streak/down_streak`）此前完全未实现——若将来开启 `qhd_enabled`，规则会因缺列不可达（**D-22 同类缺陷的第三次出现**：D-22 修 S5、D-25 补 K3/K5、本次补 D1-D3）。现全部实现并有单测（周环比 7.14% → streak 1；6.67% → streak 2）。
- **2026-09-22 `volume_ratio_5d` 口径结案**：03 §2.1 定义为「当日成交额 / MA(成交额,5)」，与现实现一致 → M1 §6 登记的存疑项关闭，不改代码。
- **停更保护下沉**：`STALE_DAYS` 与 `streak` 收拢到 `common.py`，`demand.add_energy` 显式做"距最后观测超 30 天置空"。
