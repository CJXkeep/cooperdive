# 迭代设计与实现记录（iterations）

> 建立：2026-09-20 | 上位基准：[06-设计决议与迭代计划](../06-设计决议与迭代计划.md)
> 定位：`01`~`06` 是**基准**（决议 / DDL / 验收标准）；本目录是**执行**（展开设计 + 任务状态 + 实现记录）。

## 1. 为什么要拆

06 是决议基准（ADR），随迭代只增不减。若把执行细节（接口契约、实现顺序、调试记录、偏差说明）
都堆进 06，基准文档会失去「一页看完全局」的作用。因此按里程碑拆分为独立迭代文档：

| 层 | 文档 | 职责 | 更新时机 |
|---|---|---|---|
| 基准 | `01`~`06`（尤其 06） | 决议、数据源结论、DDL、验收标准 | 出现新决议时追加 D-xx |
| 执行 | `iterations/Mx-*.md` | 本迭代的设计细化、任务状态、**实现记录（note）**、偏差与遗留 | 迭代进行中持续更新 |
| 索引 | 本 README | 模板、状态约定、索引 | 体系调整时 |

**冲突处理**：迭代文档与 `01`~`06` 冲突时，**以 `01`~`06` 为准**。
迭代中产生的新决定：先记入迭代文档 §5「实现记录」；重要者升格为 06 的 D-xx 决议，并在两处互相回链。

## 2. 命名与状态约定

- 文件名：`M{序号}-{短名}.md`，与 06 §4.2 里程碑总表一一对应。
- 状态标记：⬜ 未开始 / 🟡 进行中 / ✅ 完成 / ⚠️ 完成但有偏差（须在 note 说明原因） / ⏭ 跳过（须写明原因）。
- 任务编号沿用 06（`M0-1`、`M1-3`…），不重新编号，保证与 06 §4.x 可对照。

## 3. note 纪律（写实现记录时遵守）

1. **非平凡变更必须留痕**：改行为、接口、表结构、流程、测试策略的变更，必须在**同一次提交**中更新本迭代文档（任务行 note 或 §5 实现记录）。
2. **写事实，不写计划**（Kill Spec-speak）：§5 只记「已经是什么 / 为什么」，不出现"计划/预计/打算"；没做完的移入 §6「遗留与偏差」。
3. **决策必带备选**：非直觉的技术选择按「选择 / Alternatives（为何不选）/ 代价」三段记录——代码只说明现在怎么跑，讲不清为什么不用更简单的 B。
4. **被否决的路线不删除**：保留在 §5，重要者升格到 [`../06` §8「已否决方案」](../06-设计决议与迭代计划.md)，防止后续 Agent 重提。
5. **重要决定升格**：影响跨迭代/跨模块的决定，升格为 06 的 `D-xx` 并在 §5 回链编号（如【D-22】）。
